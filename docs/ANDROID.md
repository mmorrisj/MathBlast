# Shipping MathBlast on Google Play

The game is a plain web app, so getting it into the Play Store means wrapping
it in an Android container. Nothing about the game changes.

## The two routes, and why this repo takes the second

**A Trusted Web Activity** (via Bubblewrap) ships an APK that is really Chrome
pointed at your live site, verified with Digital Asset Links. It is the lighter
wrapper, but it needs the game hosted at a public HTTPS URL forever, and a
first launch with no signal shows a blank screen.

**Capacitor** copies the web assets *into* the app. There is no host to keep
alive, no asset-links file to get wrong, and the game works on a plane the
moment it is installed. MathBlast makes no network calls at all once it is
running, so nothing is lost by embedding it. That is what `capacitor.config.json`
is set up for.

## What is already done

- `manifest.webmanifest` — fullscreen, landscape-locked, with 192/512 icons and
  a maskable variant so Android does not letterbox it into a white circle.
- `sw.js` — precaches all 43 files, generated by `tools/gen-sw.mjs`. `npm test`
  fails if it is stale.
- The typeface ships in `assets/font/`. It used to come from Google Fonts,
  which an installed app cannot reach offline.
- Wake lock, orientation lock, fullscreen-on-first-touch, safe-area insets, and
  Android's back button closing overlays instead of the app.

## Getting it onto a phone today, without any of this

The fastest way to see MathBlast as an app is to skip the build entirely.
Because the game is served straight from the repo root with no build step,
GitHub Pages can host it as-is:

**Settings → Pages → Source: "Deploy from a branch" → `main` → `/ (root)`**

A minute later it is live at `https://<user>.github.io/<repo>/`. Open that in
Chrome on the phone and use **⋮ → Add to Home screen**. What you get is the
same app the Play Store build would install: its own icon, no browser chrome,
fullscreen and landscape-locked, and it keeps working with the network off.

What it does *not* get you is a Play Store listing — no search, no install
count, no way for anyone to find it who does not have the link. That is the
only thing the rest of this document buys.

Every URL the app ships is relative so that this works from a subpath; a test
asserts it, because one absolute path is enough to break it.

## Building the app

```sh
npm install              # Capacitor CLI -- packaging only, nothing ships to the browser
npm run build            # regenerates sw.js and www/
npx cap add android      # once, generates android/ (gitignored)
npm run app:apk          # debug APK -> android/app/build/outputs/apk/debug/
```

`npm run app:open` opens the project in Android Studio, which is the easier way
to do the signing setup below.

Requires the **Android SDK** (platform 36, build-tools) and JDK 17+. Android
Studio installs both; `sdkmanager` alone is enough for CI.

## Signing and uploading

1. **One-off setup.** A Play Console developer account is $25, once.
2. **An upload key**, which must never be committed (`.gitignore` covers
   `*.keystore`/`*.jks`):
   ```sh
   keytool -genkey -v -keystore mathblast-upload.jks \
     -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
   Point `android/app/build.gradle` at it via a `signingConfigs` block reading
   from `~/.gradle/gradle.properties`, so the passwords stay out of the repo.
3. **Build the bundle** — Play takes `.aab`, not `.apk`:
   ```sh
   npm run app:aab      # -> android/app/build/outputs/bundle/release/
   ```
4. **Upload** to an internal testing track first. It reaches your own device
   through Play in a few minutes and catches the things an emulator will not:
   real touch targets, the notch, and how the audio behaves against the phone's
   own mixer.

## What Play asks for beyond the binary

None of this is code, and all of it blocks release:

- A privacy policy at a public URL. MathBlast collects nothing and sends
  nothing — scores and profiles are `localStorage` on the device — but the
  policy still has to exist and say so.
- A Data Safety declaration, which for this game is "no data collected".
- A content rating questionnaire.
- Store listing: title, short and full description, a 512×512 icon
  (`assets/icons/icon-512.png`), a 1024×500 feature graphic, and at least two
  landscape phone screenshots.
- **Because this is an educational game aimed at children, the Families policy
  applies.** That means declaring a target age group, and the app must have no
  ads, no analytics SDKs and no external links. MathBlast has none of those
  today; adding any of them later changes what you have to declare.

## Also worth knowing

The same PWA works on iOS as a home-screen app. The App Store route is harder
than Play but not closed: guideline 4.2 rejects thin wrappers around a live
website, which a fully bundled offline game is not. It needs a Mac, $99 a year
and its own set of declarations. [COMPLIANCE.md](COMPLIANCE.md) puts both stores
side by side.
